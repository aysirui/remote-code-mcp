## 商用、分叉与网络服务

AGPL 允许商业使用、收费分发、收费部署和提供支持。它不要求所有商业用户向公司购买授权，也不禁止合规的竞争服务。

| 场景                                               | 主要许可边界                                                                           |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 原样分发项目源码或创建公开源码分叉                 | 保留必要版权、许可和免责声明，并附带许可证                                             |
| 分发受 AGPL 覆盖的修改源码                         | 标明修改及日期，按 AGPL 许可覆盖的整体作品                                             |
| 分发可执行程序、构建产物或容器镜像                 | 按第 6 条提供与所分发版本对应的源码；仅链接一个不匹配的上游版本不够                    |
| 修改程序后通过网络提供 SaaS / API 等服务           | 按第 13 条，向所有与该修改版本远程交互的用户显著提供免费获取对应源码的机会             |
| 仅运行未经修改的服务端版本                         | 第 13 条的新增义务以修改程序为触发条件；向浏览器发送前端代码等分发行为仍需遵守相关条款 |

“向接收者或交互用户提供对应源码”不等于必须在公共 GitHub 仓库发布，也不要求向本项目提交 Pull Request。接收者依法获得的再分发权不能被额外保密或禁止商用条款剥夺。

## 对应源码的范围

对应源码包括生成、安装、运行和修改受许可覆盖版本所必需的源码及相关脚本，具体范围按许可证第 1 条判断。不能只提供补丁片段或忽略服务中实际运行的修改。

AGPL 不会仅因程序部署在同一服务器上，就要求公开所有无关系统。某个插件、模块或集成是否构成受许可覆盖的组合作品，需要结合代码关系及具体实现判断，不能仅凭“独立服务”或“通过 API 连接”的名称确定。

用户通过 RCM 读取、编辑、搜索、提交或构建的独立工作区项目，不会仅因使用本工具而自动受 AGPL 约束。服务用户数据、令牌、私钥和生产凭据也不是应随源码公开的内容；需要的配置结构可提供不含密钥的示例。

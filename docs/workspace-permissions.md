# Remote Code MCP 工作区权限与数据流向

MCP 客户端通过 RCM 文件工具只能访问已授权工作区内、通过本机路径检查的文件。新工作区默认只读。操作由本机 Runtime 执行，Server 会转发文件内容等调用数据，但不会把它们作为 Server 或 Console 的业务数据持久化。

## 谁决定一次调用能否执行？

1. MCP 客户端通过 OAuth 获得访问 RCM Server 的授权。
2. Server 核对用户、设备和工作区的归属，再通过已有的设备连接转发请求。
3. Runtime 核对工作区是否启用、读写权限和工具策略。需要审批的操作在收到批准后，还会检查最新授权再执行。

工作区按 Server 独立授权。切换 Server 后，同一个本地目录需要在目标 Server 的配置中有对应授权。

## 哪些操作需要审批？

| 操作                      | 权限与审批条件                                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| 读取或搜索文件            | 需要工作区读取权限，遵循 File 策略和本地路径检查。                                              |
| 查看 Git 状态、历史或差异 | 需要工作区读取权限，遵循 Git 策略。                                                             |
| 写入、移动或删除文件      | 需要工作区写入权限，遵循 File 策略。高危递归删除还需本机单次审批。                              |
| Git 暂存和提交            | 需要工作区写入权限，并须通过本机单次审批。                                                      |
| 运行命令                  | 需要工作区写入权限。登记命令遵循 Command 策略。允许命令执行时，临时程序和参数仍需本机单次审批。 |

File、Git 和 Command 分别支持禁止、审批执行和完全允许。命令以 Runtime 进程的系统账号权限运行，可能访问工作区之外的文件和网络。审批规则不提供操作系统沙箱隔离。[命令执行规则](./usage.md#命令执行)

## 文件内容会经过哪里？

| 组件         | 数据如何处理                                                                   |
| ------------ | ------------------------------------------------------------------------------ |
| 本机 Runtime | 保存本地目录和设备凭据，执行文件、Git 或命令操作。                             |
| RCM Server   | 转发执行所需的内容，可以接触转发数据。审计记录仅保存允许的脱敏元数据。         |
| MCP 客户端   | 接收调用结果，例如文件正文或命令输出。后续保存和使用取决于客户端及其数据政策。 |

Server 和 Console 的持久化业务数据不包括工作区绝对路径、文件正文、命令完整参数、审批详情和 AI 对话。代理和 APM 的日志配置也会影响数据留存，Runtime 的本地诊断日志可能包含操作参数。查阅[项目安全说明](https://github.com/aysirui/remote-code-mcp/blob/main/SECURITY.md)和 [Runtime 终端日志](./usage.md#runtime-终端日志)。

## 如何收回访问权限？

在 Runtime 中撤销对应 Server 下的工作区授权，可收回对该本地目录的访问。也可以在 [官方控制台](https://rcmconsole.aysirui.com/) 撤销某个设备或 AI 客户端的授权，阻止后续调用。客户端已经收到的内容由其自身的数据保留规则处理。

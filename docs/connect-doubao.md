# 豆包 MCP 接入与使用

通过豆包工作桌面客户端的自定义连接器，可以直接接入 RCM 官方在线 MCP Server，在聊天中访问已授权设备上的代码工作区，无需在豆包开放平台开发、上传或发布插件。

本文的连接器配置、OAuth 授权及工作区文件读取流程已完成实际验证。不同客户端版本的界面及功能可能有所差异。

## 接入前准备

- 在 [官方控制台](https://rcmconsole.aysirui.com/) 注册或登录 RCM 账号。
- 按 [Runtime 使用指南](./usage.md) 在存放代码的设备上启动 Runtime，连接官方 Server `https://rcm.aysirui.com`，完成设备配对并授权测试工作区。
- 安装并登录支持自定义连接器的豆包工作桌面客户端。首次验证建议使用只读测试工作区。

## 1. 新建自定义连接器

打开豆包工作，依次进入：

**插件 · 技能 · 工作台 → 插件 → 添加 → 新建自定义连接器**

1. 点击左侧导航中的「插件 · 技能 · 工作台」。
2. 在页面顶部选择「插件」标签。
3. 点击右上角「添加」，在下拉菜单中选择「新建自定义连接器」。

## 2. 配置 RCM MCP Server

在自定义连接器配置窗口中填写以下信息：

| 配置项         | 填写内容                      |
| -------------- | ----------------------------- |
| 服务器名称     | `rcm`                         |
| 传输类型       | HTTP                          |
| 服务器 URL     | `https://rcm.aysirui.com/mcp` |
| 自定义 Headers | 留空，无需添加                |

豆包界面中的 HTTP 对应 RCM 使用的远程 Streamable HTTP 传输方式。认证通过后续 OAuth 流程完成，无需手动填写 Access Token 或 Authorization Header。

确认配置后点击「保存」。

::: tip
豆包提示自定义连接器仅支持在本地电脑中使用。这里指豆包客户端侧的连接器使用限制；RCM 所访问的代码工作区可以位于另一台已绑定、授权且在线的设备上。
:::

## 3. 启用连接器并完成 OAuth 授权

1. 返回「插件 · 技能 · 工作台」，点击右上角「管理」。
2. 切换到「连接器」标签，在「个人」分类下找到 `rcm`。
3. 开启 `rcm` 右侧的开关，按客户端提示进行 OAuth 授权。
4. 在 RCM 授权页面使用与 Runtime 配对时相同的 RCM 账号，核对客户端和授权范围后点击「同意授权并继续」。
5. 按提示返回豆包工作客户端，确认 `rcm` 连接器保持启用状态。

完成授权后，即可在聊天中请求使用 RCM 工具。实际操作仍受到 Runtime 的工作区授权、读写权限和审批策略限制。

## 4. 在聊天中使用 RCM

点击「新工作任务」，在聊天输入框中通过自然语言指定使用 RCM 连接器，不需要手动填写工作区 ID 或 MCP 工具参数。

### 查看设备和工作区

```text
使用 rcm 工具查看设备列表和工作区列表。
```

通过返回结果确认目标设备是否在线、工作区是否已授权。

### 读取并解释代码文件

```text
使用 rcm 工具读取 rcm-test 工作区中的 README.md 文档，并进行解释说明。
```

实际验证中，豆包依次调用了以下工具：

1. `workspace_list`：查找名为 `rcm-test` 的工作区。
2. `file_list`：查看工作区根目录，确认文件名称。
3. `file_read`：读取 README.md 正文并返回文件摘要。

豆包根据工具返回的实际文件内容进行解释。使用时请将示例中的工作区名称和文件路径替换为自己的项目，并注意文件名大小写。

### 修改工作区文件

首次写入前，在 Runtime 中开启测试工作区的写入权限，建议将 File 策略设为审批执行。

```text
使用 rcm 工具修改 rcm-test 工作区中的 README.md，
在末尾添加一行“通过豆包更新”。
先读取文件，再进行修改，完成后重新读取确认结果。
不要提交 Git。
```

如果 Runtime 发出审批请求，请核对操作内容后批准。修改已有文件时，应使用读取结果中的 SHA-256 进行写入版本检查。

对于任务中已经生成到本地的图片，可用 `file_write` 的 `stream` 模式领取一次性 PUT 地址，再从持有文件的终端上传原始字节。地址有效期为 5 分钟，PUT 无需 OAuth 请求头。见 [文件流验证](./local-development.md#_8-验证连接及文件流)。

### 查看 Git 状态

```text
使用 rcm 工具查看 rcm-test 工作区的 Git 状态和未提交的代码差异，不要修改文件。
```

以上修改文件及 Git 操作为使用示例，实际执行取决于当前客户端工具调用能力和工作区权限。可以通过豆包的工具调用记录及 [官方控制台](https://rcmconsole.aysirui.com/) 的操作记录核对执行情况。

## 常见问题

| 现象                       | 处理方式                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| 找不到新建自定义连接器入口 | 确认正在使用支持自定义连接器的豆包工作桌面客户端，而非普通聊天网页或其他不支持该功能的版本。 |
| 保存后找不到 RCM           | 进入「插件 · 技能 · 工作台 → 管理 → 连接器」，在「个人」分类中查找。                         |
| 启用连接器后授权失败       | 确认传输类型为 HTTP，URL 为官方 `https://rcm.aysirui.com/mcp`，按客户端提示重新授权。        |
| 聊天中未调用 RCM           | 确认连接器已启用且完成 OAuth 授权，在指令中明确指定使用 rcm 工具。                           |
| 工作区列表为空             | 确认 OAuth 使用的 RCM 账号与 Runtime 配对账号一致，并已授权工作区。                          |
| 文件读取或修改失败         | 检查目标设备是否在线、工作区是否启用、文件路径及读写权限和审批策略。                         |

更多权限说明见 [工作区权限与数据流向](./workspace-permissions.md)。
